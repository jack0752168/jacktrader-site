掛單 vs 吃單手續費完整解析：切到掛單，2026 年少付手續費

多數交易者從來沒碰過離自己最近、也最便宜的一個手續費折扣。它不用錢、不用達到任何交易量等級、也不用囤 BNB——你只要成交在盤口的另一邊就好。這篇會講清楚 2026 年幣安與 OKX 的掛單、吃單費率各是多少、為什麼交易量越大差距滾得越兇、怎麼用 post-only 保證以掛單成交，以及返傭如何疊在這一切之上。

先講結論

你送出的每一張單，不是掛單（maker）就是吃單（taker）：

  • 掛單——你掛出一張停在盤上等待的限價單。你提供流動性，所以付較低的掛單費。
  • 吃單——你送出一張立即撮合現有掛單的單（市價單，或報價穿越價差的限價單）。你移除流動性，所以付較高的吃單費。

現貨上這個差距很小甚至為零。但在合約上差距很大：幣安收 0.0200% 掛單 vs 0.0500% 吃單——吃單那邊貴 2.5 倍。如果你交易量夠大，決定用掛單成交，就是你能自己控制、報酬最高、力氣最省的一刀。接著再用一層 sub-broker 返傭 把剩下的費用退回一部分。

掛單與吃單到底是什麼

盤口有兩側——低於現價的買方掛單、高於現價的賣方掛單。最佳買價與最佳賣價之間的距離就是價差。

  • 若你掛出一張低於最佳賣價的買入限價單，它還不能成交，於是以等待成交的買單身分掛上盤口。之後別人往下賣打到它時，你就是掛單方。
  • 若你送出市價買單，或掛出一張報價等於或高於最佳賣價的買入限價單，它會立即撮合現有的賣方掛單。你就是吃單方。

身分是在成交當下決定的，不是看你的意圖。一張限價單不會自動變成掛單——如果它穿越了價差，就會以吃單成交。唯一能確定的方法是 post-only 旗標（下面會講）。

怎麼真的以掛單成交

  1. 用限價單，別用市價單。市價單永遠是吃單。限價單可以是掛單——只要它不穿越價差。
  2. 開啟 post-only。幣安與 OKX 都提供 post-only（只掛單）旗標（下單面板上的勾選框、API 上的一個 time-in-force 選項）。它保證你的單要嘛以掛單掛上盤口、要嘛被拒絕——它永遠不會以吃單成交。這是鎖定掛單費最安全的方法。
  3. 報價在盤內，別穿越。要買，掛在最佳買價或更低；要賣，掛在最佳賣價或更高。你用即時性換來更便宜的費率、而且常常還換到更好的價格。
  4. 把機器人設定成掛單成交。在每個網格層掛出等待成交限價單的網格機器人，天生就是掛單方——這正是網格為什麼省手續費的一大原因。如果你的機器人用市價單追價，你每次成交都在付吃單費。見 網格機器人手續費優化。
  5. 接受這個取捨。如果行情跑離你的價位，掛單可能不會成交。對被動、均值回歸與網格策略而言這沒問題。對於「成交確定性比省 3 個基點更重要」的動量進場，有時吃單才是對的選擇——只要你清楚它的成本就好。

返傭怎麼疊在最上面

切到掛單降低的是交易所向你收的毛費用。sub-broker / 聯盟返傭 則退還你仍要付的那筆費用的一部分——掛單或吃單都算。因為返傭是以你實際付的費用計算，它作用在你的掛單折扣之後，所以兩層節省相乘累加：

  • 掛限價 / post-only → 你付掛單費率而不是吃單費率。
  • 透過 幣安 或 OKX 返傭通道註冊 → 那筆掛單費最高 40% 退回給你，實時結算。
  • 不用 API 金鑰、不用託管——返傭記在交易所自己的聯盟帳本上。見 自架機器人怎麼綁返傭。

快速檢查清單

  • 預設用限價單，只要成交時機允許就開 post-only。
  • 記住你的合約差距——幣安與 OKX 上吃單是掛單的 2.5 倍；那是你每次吃單時選擇花掉的基點。
  • 稽核你機器人的訂單類型——確認它是在掛單、不是在穿越價差。
  • 疊一層返傭在掛單費率之上，讓兩個折扣相乘累加。
  • 每次結算對帳——把你的手續費紀錄對照返傭儀表板核一遍。

常見問題 FAQ

掛單費與吃單費有什麼差別？+
掛單（maker）訂單為盤口提供流動性——它以限價單掛在盤上等待成交，所以交易所收較低的掛單費。吃單（taker）訂單則立即撮合現有掛單、移除流動性（市價單，或穿越價差的積極限價單），因此付較高的吃單費。合約上這個差距很大：幣安 USDT 本位合約在普通等級收 0.0200% 掛單、0.0500% 吃單。
為什麼掛單費比吃單費低？+
交易所想要一個又深又有流動性的盤口。掛單者透過掛出等待成交的限價單提供流動性，所以平台以較便宜的費率回饋他們——高 VIP 等級甚至可能是負費率（返還）。吃單者消耗流動性，因此付得比較多。費率表本身就是維持盤口飽滿的誘因。
我怎麼確定我的單被當成掛單？+
用一張不會立即穿越價差的限價單，並在交易所提供時開啟 post-only（只掛單）旗標。post-only 保證你的單要嘛以掛單身分掛上盤口、要嘛被拒絕——它永遠不會以吃單成交。在幣安與 OKX 上，這是限價單下單面板上的一個勾選框、以及 API 上的一個 time-in-force 選項。
網格機器人付掛單費還是吃單費？+
看設定。在每個網格層掛出等待成交限價單的網格機器人，大多以掛單成交，這正是網格策略對手續費極度敏感的原因。若機器人被設成用市價單追價，就會在每次成交都付吃單費，可能悄悄吃光網格的利潤。
返傭對掛單費和吃單費都適用嗎？+
是。sub-broker 或聯盟返傭是以交易所實際向你收取的費用計算，無論掛單或吃單。所以返傭是疊在你已經靠掛限價單拿到的掛單折扣之上——兩層節省是相乘累加，而非互相取代。
