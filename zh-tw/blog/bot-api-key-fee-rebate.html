自架交易機器人怎麼拿返傭：API 金鑰帳戶綁定教學

決定你的機器人能不能拿返傭，只有一個關鍵事實：返傭綁在你的交易所帳戶上，不是綁在 API 金鑰、也不是綁在機器人上。想通這點，整個邏輯就清楚了——像 Freqtrade、Hummingbot、OctoBot 這類自架機器人，完全不用改一行程式就能拿到最高 40% 返傭；而部分託管機器人卻會悄悄把你那一次性的綁定花在它們自己身上。這篇就是教你把返傭綁到機器人實際交易的那個帳戶上。

先講結論

  1. 返傭住在帳戶上。當你在幣安或 OKX 綁定推薦，綁定就記錄在交易所帳戶上。該帳戶做的每一筆交易——手動、腳本還是機器人——都拿得到返傭。
  2. API 金鑰只是一把門鑰匙。機器人用 API 金鑰驗證身分去下單。建立、刪除或更換金鑰，對返傭毫無影響。金鑰本身不帶任何推薦資訊。
  3. 所以該問的從來不是「我的機器人支不支援返傭」，而是「機器人交易的那個帳戶有沒有綁返傭」。自架機器人在這點上贏，因為帳戶和綁定都在你手上。唯一會出錯的，就是讓某個託管機器人用它的推薦連結幫你註冊帳戶。

如果只記一句：先在返傭連結下自己註冊交易所帳戶，再用 API 金鑰接機器人。順序千萬別反過來。

為什麼返傭綁帳戶、不綁金鑰

返傭是交易所本來就向你收的手續費中，因為你的帳戶被歸屬到某個推薦／Sub-broker 關係，而退還的一部分。這個歸屬是帳戶的屬性，在帳戶建立時設定（若當初未歸屬，也可後續補綁）。本來就只能這樣——交易所是在每個結算週期結束時，依該帳戶的總交易量結算返傭再支付，通常是每週以 USDT 結算。

相對地，API 金鑰是帳戶層級的憑證，帶有限定權限（讀取、交易、有時還有提現）。它在層級上位於帳戶之下。你可以為一個帳戶上的五個機器人持有五把金鑰、每月為了安全更換一次，返傭完全不受影響，因為它從一開始就沒綁在金鑰上。這其實是好消息：它代表「把機器人弄安全」（只給交易權限、關閉提現、設 IP 白名單）和「拿返傭」是兩件完全獨立的事。

自架 vs SaaS 機器人：綁定權在誰手上

機器人類型誰註冊交易所帳戶你能綁自己的返傭嗎？要注意什麼
自架／開源（Freqtrade、Hummingbot、OctoBot、Jesse）你自己能——完全掌控沒什麼；只要在產生金鑰前先在返傭連結下註冊
用 API 金鑰連到你帳戶的 SaaS 機器人（多數網格／DCA 面板）你自己能——機器人只是借用金鑰確認它要的是 API 金鑰，而不是「透過我們註冊」的連結
要你透過它推薦連結註冊交易所的 SaaS／跟單平台服務商不能——你的綁定被花在它們身上想保留自己的返傭，就是要避開這種

分界線不是「自架 vs 託管」，而是底層交易所帳戶的推薦綁定權在誰手上。透過 API 金鑰連接的託管機器人沒問題；會出事的，是那種逼你透過它的連結去註冊交易所的機器人——它拿走了你本來能留住的返傭。

設定步驟

  1. 在返傭連結下註冊交易所帳戶。透過幣安返傭或OKX 返傭頁面的推薦綁定完成。這是唯一會碰到返傭的步驟，兩分鐘搞定。
  2. 照常完成 KYC、入金。綁定已經記錄好了；入金或驗證都不會改變它。
  3. 建立「僅交易」權限的 API 金鑰。關閉這把金鑰的提現權限。如果機器人跑在固定 IP 的伺服器上，再加上 IP 白名單。這是安全步驟，跟返傭無關。
  4. 把金鑰貼進機器人（Freqtrade 的 config.json、Hummingbot 的 connect 流程、OctoBot 的交易所分頁）。機器人就會在已綁定的帳戶上開始交易。
  5. 確認返傭有在累積。第一個結算週期後，返傭就應該反映機器人的交易量。因為綁在帳戶上，它會抓到機器人交易的 100%，而不是抽樣的一部分。

機器人內部的交易所手續費微調——掛單進場、BNB 折扣、交易模式選擇——可參考姊妹文Freqtrade 在幣安與 OKX 的手續費（英文），裡面逐項拆解了決定你付掛單還是吃單費的設定。

實算範例——一個每月 400 萬美元的自架機器人

你在自己的 VPS 上跑 Freqtrade，交易 USDT 本位永續，每月周轉名目 400 萬美元。假設混合有效費率為 0.04%（掛單進場、吃單出場的現實組合）：

  • 每月手續費 ≈ 400 萬 × 0.04% = 1,600 美元（約每年 19,200 美元）。
  • 如果帳戶沒綁返傭，你全額付掉。機器人替返傭方賺不到、你也拿不到。
  • 如果同一帳戶綁了最高 40% 返傭：≈ 1,600 × 40% = 每月退 640 美元，官方後台實時結算 USDT——約每年退回 7,680 美元，而機器人、策略、API 金鑰全都原封不動。

策略沒變、程式沒變。兩種情境唯一的差別，只是你在產生 API 金鑰之前用哪種方式註冊帳戶。這就是全部的槓桿——也是為什麼「先綁、後接」這麼重要。

常見錯誤

  • 想要自己的返傭，卻透過機器人平台的連結去註冊交易所——這會把你的綁定花在它們身上。請自己註冊交易所。
  • 以為新的 API 金鑰會重設或產生返傭——完全不會。重點永遠是帳戶綁定。
  • 把 API 金鑰或密碼交給「返傭機器人」——正當返傭兩者都不需要。交易所是用你綁定的帳戶來計算返傭；危險訊號清單見加密返傭安全嗎（英文）。
  • 忘了資金費率——返傭砍的是交易手續費，不是資金費率（英文）。跑永續機器人時，兩者都要算進去。

把它放進更大的手續費版圖

對機器人來說，綁返傭是會改變每一條手續費的兩個槓桿之一，另一個是掛單路由。不同類型機器人的費率差異，見網格機器人手續費優化；想直接比較幣安與 OKX 的費率，見幣安 vs OKX 手續費。返傭是那個你拉一次就能一直留著的槓桿——但前提是它綁在機器人實際交易的那個帳戶上。

常見問題

返傭是綁在我的 API 金鑰上，還是綁在交易所帳戶上？+
綁在交易所帳戶上。推薦／返傭綁定是在註冊時記錄在帳戶本身（或在幣安、OKX 上，於符合資格的期間內為一個尚未綁定的既有帳戶補綁）。API 金鑰只是讓機器人在該帳戶下單的憑證——建立、刪除或更換金鑰都不會改變返傭。所以只要帳戶綁了返傭，機器人透過任何一把 API 金鑰送出的每一筆委託都算數；如果帳戶沒綁，任何金鑰都補不回來。
像 Freqtrade、Hummingbot 這類自架機器人能拿到返傭嗎？+
可以，完全可以。自架與開源機器人連接的是你自己註冊的交易所帳戶，所以綁定權在你手上。先在返傭連結下註冊帳戶、產生 API 金鑰、貼進機器人，之後機器人做的每一筆交易都算進你的返傭。機器人軟體根本不知道有返傭這回事——它只負責下單，返傭是交易所在已綁定的帳戶上結算的。
為什麼有些 SaaS 或跟單機器人不能給我返傭？+
有些託管機器人或訊號平台會要你透過它們自己的推薦連結去註冊一個新的交易所帳戶，這等於把你那一次性的綁定花在它們身上而不是你身上。之後帳戶就綁在該服務商名下，你無法再重新綁到別的返傭。如果機器人是透過 API 金鑰連到你已經擁有的帳戶（正常模式），它不會動到你的綁定——問題只出在那些把你導去它自家註冊頁的機器人。永遠先自己註冊交易所帳戶，再用 API 金鑰接機器人。
我需要給機器人或返傭服務商額外的權限嗎？+
不需要。返傭是交易所根據你已綁定帳戶的交易量計算的——返傭服務商從不需要你的 API 金鑰、密碼或提現權限。對機器人，只要建立「僅交易」權限的 API 金鑰，並關閉提現。一個正當的返傭設定除了帳戶綁定本身之外不需要任何東西；任何人要你的密碼、開啟提現權限的金鑰、或要你把錢入金給對方，都是危險訊號。
我的機器人已經在一個既有帳戶上跑了，還能加返傭嗎？+
有可能。如果該帳戶從未綁定過任何推薦，幣安與 OKX 允許你在符合規則的前提下為既有帳戶補綁（幣安的換綁測試看的是帳戶近 90 天總交易量是否在 5,000 USD 以內，與帳戶開多久無關，且要在 30 天內做滿 150,000 USD 才生效）。你不用動機器人或它的金鑰——綁定發生在帳戶層級，機器人照常交易。如果帳戶已經綁在別處，較乾淨的做法是在返傭連結下開一個新帳戶讓機器人去跑。動手前先請對方做一次帳戶層級的查核，別自己假設。

先綁返傭，再接機器人

在最高 40% 返傭下註冊你的交易所帳戶，再把「僅交易」權限的 API 金鑰貼進 Freqtrade、Hummingbot 或任何機器人。返傭會抓到帳戶交易量的 100%，官方後台實時結算 USDT——不改策略、不開額外權限。
